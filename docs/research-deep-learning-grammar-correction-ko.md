# 딥러닝 기반 한국어 문법 오류 교정(GEC) 모델 연구 — Claude Sonnet 기준 재정의

> 이다빈(2021), 「딥러닝 기반의 한국어 문법 오류 교정 모델 연구」, 경기대학교 대학원 문헌정보학과 석사학위논문(지도교수: 최성필). 80쪽. Paul이 전달한 「한국어 AI 논문 모음」 배치 중 한 편으로, 다른 논문들(쓰기교육·채점기준)과 달리 교육학이 아니라 **NLP 모델 구조·데이터 구축·정량평가**를 다루는 기술 논문이다.
>
> **이 문서의 목적**: 이 논문은 "전용으로 학습시킨 한국어 GEC 모델"을 제안한다. jabi는 현재 전용 GEC 모델 없이 범용 LLM(Claude Sonnet)에 문법 오류 판단을 맡기고 있다. 이 논문의 수치와 한계를 근거로, **전용 모델을 새로 학습시킬 가치가 있는지 아니면 Claude로 이미 충분한지**를 판단한다.

---

## 연구 개요

- **제안 모델**: Transformer 구조에 (1) 인코더를 사전학습 언어모델 **KoELECTRA**로 교체하고, (2) 디코더 출력단에 **Copying mechanism**(요약 분야에서 검증된, OOV 단어를 입력에서 그대로 복사해오는 계층)을 추가. 비교 대상으로 순수 Transformer, Transformer+Copying mechanism(사전학습 LM 없음) 두 모델을 별도로 학습해 3자 비교.
- **학습 데이터**: 공식 한국어 GEC 병렬 코퍼스가 존재하지 않는다는 문제를 저자가 직접 지적하고, 신문기사·AI-HUB 한영번역 코퍼스의 "정상 문장"에 **5가지 방법론으로 오류를 인위적으로 주입**해 병렬 데이터를 자체 생성했다: ① 발음 기반 오류(G2PK로 자소→음소 변환), ② 문법 규칙 기반 오류(조사 이/가·은/는·에게/께 등을 틀리게 치환), ③ 서술어 어미 변경(편집거리 기준으로 그럴듯한 오류 어미로 치환), ④ 문장부호 변경, ⑤ 띄어쓰기 오류. 5가지를 합쳐 총 **254,345,279쌍**(약 2.5억 쌍)을 생성했고, 이 중 학습 232만/실험 23만/평가 4.6만 쌍을 사용.
- **평가**: 정량평가(BLEU-1~4, GLUE, Precision/Recall/F0.5)와 정성평가(손으로 뽑은 6개 예시의 "문법교정 여부"·"자연스러움") 두 트랙. 제안 모델이 세 모델 중 전 지표 최고 성능: **BLEU-1 0.9010, GLUE 0.7843, Precision 0.5741, Recall 0.5740, F0.5 0.5740**.
- **핵심 주장**: 사전학습 언어모델(KoELECTRA)을 인코더로 쓰는 것이 Copying mechanism 단독 추가보다 성능 기여가 크다.

## 핵심 발견 1 — 조사(助詞) 오류 교정을 가른 건 "구조"가 아니라 "사전학습 언어모델의 유무"였다

논문 표18의 정성평가 예시: 입력 "전국코오롱스포츠매장**와**코오롱몰에서" → 정답 "매장**과**"(조사 와/과 오류). 결과는 극명하게 갈렸다.
- 순수 Transformer: 조사는커녕 "코오롱"을 "위원장"으로 통째로 잘못 바꿔 문장 자체가 붕괴.
- Transformer+Copying mechanism(사전학습 LM 없음): 불필요한 단어 변경은 없었지만 **조사 오류(와→과)를 끝내 고치지 못함**.
- Transformer+Copying+KoELECTRA(제안 모델): 조사만 정확히 교정.

→ **재정의**: 이 논문 자체가 "조사 교정은 강한 사전학습 언어모델이 있어야 풀린다"는 것을 실증한 셈이다. KoELECTRA-base는 2020년 기준 중형 한국어 LM이다. Claude Sonnet은 그보다 학습 데이터·파라미터 규모가 몇 자릿수 큰 범용 사전학습 LM이므로, 같은 원리로 조사 오류 교정에 최소한 KoELECTRA 수준 이상의 성능을 기대할 근거가 있다. jabi가 조사 오류를 잡기 위해 별도 GEC 모델을 새로 학습시킬 필요는 낮다 — 이미 그보다 강한 LM(Claude)을 쓰고 있기 때문이다.

## 핵심 발견 2 — 2.5억 쌍을 학습해도 F0.5는 0.574에 그쳤다

Precision·Recall·F0.5 세 지표 모두 제안 모델 기준 약 **0.57** 수준이다(0.529~0.548 사이인 비교 모델보다는 높지만, 여전히 오답이 절반 가까이 남는 수준). 이는 학습 데이터 규모(2.5억 쌍)의 문제가 아니라, 인위적으로 주입한 5종 오류 패턴이 실제 문법 오류의 다양성을 다 담지 못했기 때문으로 보인다(저자도 결론에서 "제안한 문법오류 생성방법으로는 처리할 수 없는 문법적 오류가 존재할 것"이라 명시).

→ **재정의**: 대규모 데이터를 투입해 전용 모델을 밑바닥부터 학습시켜도 정확도 상한이 이 정도라면, 1인 개발자가 리소스를 들여 재현할 실익이 크지 않다. 반대로 Claude는 이미 훨씬 큰 말뭉치로 사전학습되어 있고 별도 GEC 파인튜닝 없이도 문맥 기반 교정이 가능하므로, "전용 모델을 직접 학습시키자"는 선택지는 이 수치 하나만으로도 낮은 우선순위로 내려간다.

## 핵심 발견 3 — 학습 데이터는 100% 인공 주입 오류이며 실제 학습자 오류가 아니다

한국어 공식 GEC 병렬 코퍼스가 없다는 것 자체가 이 논문의 출발점이다. 그래서 정상 문장에 규칙적으로 오류를 "심어서" 데이터를 만들었다 — 실제 외국인 학습자가 쓴 오류 문장이 아니다. 즉 이 모델의 F0.5 0.57은 **자기가 만든 인공 오류 패턴에 대한 성능**이지, jabi 사용자처럼 실제 비원어민이 쓰는 자연스러운 오류에 대한 성능이 아니다.

→ **재정의/적용**: 이 갭은 jabi 쪽에 유리하게 작용할 수도, 불리하게 작용할 수도 있다 — 검증이 필요하다는 뜻이지 이 논문의 수치를 신뢰 상한으로 삼을 이유는 없다. 반면 이 논문의 "5가지 오류 생성 방법론" 자체는 **jabi가 자체 평가셋을 만드는 데 그대로 재사용 가능한 레시피**다(반영 후보 참고).

## 핵심 발견 4 — "문장당 오류 1개"라는 설계 제약, 실제 학습자 문장과는 다른 조건

논문 1.4(연구의 제한점)에서 저자가 직접 명시: 학습 데이터는 문장마다 오류가 하나만 포함되도록 구축했기 때문에, **여러 문법 오류가 한 문장에 중첩되면 처리가 어렵다**. 실제 TOPIK 작문 등 jabi가 다루는 학습자 문장은 조사+띄어쓰기+어미 오류가 한 문장에 동시에 나타나는 경우가 흔하다.

→ **재정의**: 이는 "전용 모델이 좁게 설계되어 겪는" 구조적 한계이며, 오류 조합별로 학습 데이터를 다시 설계해야 해결된다. 반면 Claude 같은 범용 LLM은 문장 전체를 한 번에 문맥적으로 판단하므로 오류가 몇 개든 동시에 존재해도 원리상 동일한 방식(하나의 프롬프트)으로 대응한다 — 오류 개수별 재학습이 필요 없다. jabi가 다루는 실제 사용자 문장의 특성(복수 오류 동시 발생)을 고려하면 이 지점은 범용 LLM 쪽이 구조적으로 더 적합하다.

## 핵심 발견 5 — 정성평가가 6개 예문 손수 분석에 불과함(저자도 "일반화 어렵다" 인정)

정성평가는 5가지 오류 유형에서 각 1문장씩, 총 6개 예시만 골라 세 모델의 출력을 비교한 것이다. 저자 스스로 "일부 예시를 분석한 결과이므로 일반화하기 어렵다"고 명시한다.

→ **재정의**: 학술적 엄밀성 면에서는 이 논문의 약점이지만, jabi 입장에서는 반대로 기회다 — jabi는 실사용자의 실제 문장·피드백 로그를 대량으로 쌓을 수 있는 위치에 있으므로, 이 논문보다 훨씬 신뢰도 높은 "Claude 교정 정확도 자체 평가"를 실사용 데이터 기반으로 구축할 수 있다.

## 핵심 발견 6 — "문법규칙 기반 오류"가 정확히 jabi가 이미 짚은 조사 오류(이/가, 은/는, 에게/께)와 일치

`docs/research-ai-korean-writing-synthesis-ko.md` 등 기존 jabi 리서치에서 확인된 "고급 학습자도 반복하는 고착화된 조사 오류(이/가, 을/를)"가, 이 논문의 5가지 오류 생성 방법론 중 "문법규칙에 기반을 둔 오류 생성"(표8)이 다루는 예시와 정확히 겹친다(이/가, 은/는, 에게/께 조사 치환). 서로 독립적인 두 자료가 같은 오류 범주를 한국어 문법 오류의 핵심으로 지목한 셈이다.

→ **재정의**: 조사 오류가 정말로 최우선 타겟이라는 근거가 한 번 더 쌓였다. jabi가 향후 문법 코칭이나 미니게임 콘텐츠에서 오류 카테고리를 우선순위화한다면 조사류를 최상위에 두는 것이 논문·리서치 양쪽에서 뒷받침된다.

## 참고 — jabi 현재 코드 상태 확인 메모

`hub/app/topik2/topik2.js`를 직접 확인한 결과, 파일 상단 주석에 "TOPIK II — Writing Q51–54 formative scorer (**rules only, no AI/Lemon**)"라고 명시되어 있다 — 즉 현재 이 파일 자체는 규칙 기반 채점만 수행하며, 생성형 AI(Claude) 호출은 이 파일에 직접 연결되어 있지 않다(관련 AI 호출은 `api/_polish.js` 등 다른 용도로 확인됨). 이 문서의 "전용 GEC 모델 vs Claude" 비교는 향후 jabi가 문법 코칭/첨삭에 생성형 AI를 붙일 때를 전제로 한 전략적 판단이며, 현재 topik2.js의 실제 배선 상태와는 별개임을 밝혀둔다. `hub/app/**`는 이번 조사에서 읽기만 했고 수정하지 않았다.

## 반영 후보

1. **오류 주입 미니 평가셋 구축** — 논문의 5가지 오류 생성 방법론(특히 조사 치환·띄어쓰기 삭제)을 빌려, 정답 문장에 오류를 자동으로 심은 20~30문장짜리 회귀 테스트셋을 만들고 jabi의 AI 피드백이 이를 얼마나 잘 잡아내는지 주기적으로 점검.
2. **프롬프트에 "복수 오류 동시 존재" 명시** — 전용 모델이 구조적으로 놓치는 지점(문장당 오류 1개 가정)을 역으로 활용해, Claude 프롬프트에 "한 문장에 조사·띄어쓰기·어미 오류가 동시에 있을 수 있으니 전부 짚어라" 원칙을 명문화.
3. **전용 GEC 모델 자체 학습은 보류** — F0.5 0.57이라는 이 논문의 상한과 학습 비용을 볼 때 지금 스코프에서는 이득 대비 비용이 낮음. "하지 않을 것"으로 명시적으로 남겨두는 결정.
4. **particle-snap 게임 오답 보기 다양화** — 논문 표8의 조사 오류 예시(이/가, 은/는, 에게/께, 와/과)를 게임 오답 뱅크 설계 참고 자료로 검토.
5. **G2PK류 발음→표기 변환 아이디어를 맞춤법 미니게임 소재로 검토** — "발음대로 적으면 틀리는 표기" 유형 콘텐츠 아이디어(모델 학습과는 무관, 콘텐츠 소재 차원).
