> **정정 (2026-07-26, 같은 날 늦게):** 아래 §1에서 "시계열 없이는 계산 불가능"이라 썼는데, 그 사이 Cursor가 `state.attempts[]`(회차별 scorePct) · `state.readinessLog[]`(최근 12회 추이) · `tagStrengthRows()`(태그별 강약)를 **localStorage 안에서** 구현 완료함(`renderAnalysis()`, app.js). `estimateReadiness()`는 최근 3회 평균×0.65 + 마지막 점수×0.35 가중 공식 — 아래 §3에서 제안한 "3회 중 2회" 게이트보다 더 정교함. **즉 기기 내 계산은 이미 해결됨.** 아래 백엔드 DB 제안은 여전히 유효하지만 시급성이 낮아짐 — 실제로 필요해지는 시점은 **기기 간 동기화(D11)나 Lemon Squeezy 결제로 계정이 생기는 순간**으로 좁혀서 봐야 함.

# 리서치+제안 — 데이터베이스 · 성장 시각화 · TOPIK 응시 판단 기준 (2026-07-26, Claude)

> 목적: D2(준비도 % 공식)·D3(개별 분석 페이지)·D11(계정·동기화)이 정책 레벨(`docs/handoff-growth-character-ko.md`)에선 확정됐지만 "구현 시 조정"으로 남겨진 부분 — 실제 수식·데이터 모델·시각화 방식을 제안. 기존 결정(D1/D17 임계값, "합격 n%" 단정 금지 톤)은 그대로 존중.

---

## 1. 지금 데이터베이스가 왜 더 필요한가 — 현재 상태 진단

`hub/app/js/app.js` 확인 결과: **현재는 100% `localStorage`뿐, 백엔드 DB가 전혀 없음.**

```js
state.srs[tag]        = { count, nextReview, ease, intervalDays }   // SRS 상태, 누적값만
state.learner.byTag    = { hints, wrongs, corrects }                // 태그별 누적, 시계열 아님
state.learner.choiceWrong[questionId]                                // 문항별 오답 이력
state.xp / state.streak
```

이게 왜 문제인가:
- **D11(계정·동기화, "처음부터 로그인·기기 간 동기")이 구현 안 됨** — 브라우저 지우면 학습 기록 전부 소실, 기기 바꾸면 이어서 못 함.
- **시계열이 없음** — "오답 개선 추이"(D3에서 이미 요구된 시각화 요소)를 그리려면 특정 시점의 스냅샷이 아니라 "회차별 기록"이 필요한데, 지금은 태그별 누적 카운트만 있어서 "지난달보다 나아졌는지"를 계산할 방법이 없음.
- **모의고사 점수 이력이 없음** — 최종 간이 모의(D1 판정 기준)를 몇 번 쳤는지, 각각 몇 점이었는지 저장하는 구조 자체가 없음. 지금 구조로는 "최근 3회 평균" 같은 계산이 불가능.

## 2. 제안하는 데이터 모델

D11에서 이미 후보로 언급된 **Supabase**(Postgres 기반, 무료 티어로 충분, 인증도 내장) 추천 — 아래 표는 이미 있는 것과 새로 필요한 것 구분:

| 테이블 | 상태 | 용도 |
|---|---|---|
| `learners` | **신규** | user_id, 모국어, 목표월, 모드(Catch/Mercy/Guide), 파트너 자음 |
| `srs_cards` | 기존 로직 이전 | 태그별 SRS 상태(현재 `state.srs`와 동일 필드) — 기기 동기화용 |
| `attempt_log` | **신규(핵심 갭)** | **문항 풀이 1건 = 1행**: user_id, question_id, tag, correct(bool), hint_used, timestamp. 지금의 `choiceWrong` 누적 대신 원자 단위 기록 → 여기서 "오답 개선 추이"·"강점/약점"을 나중에 얼마든지 재계산 가능 |
| `mock_attempts` | **신규(핵심 갭)** | **모의고사 1회 = 1행**: user_id, mock_type(미니/최종간이), score, per_skill_score(듣기/읽기), timestamp — 이게 없으면 D1/D2 판정 자체가 불가능 |
| `character_growth` | 기존 로직 이전 | user_id, char_id, stage, 점수 구성요소(참여/이해/개선) |

**핵심은 `attempt_log`와 `mock_attempts`** — 지금 앱엔 "누적 합계"만 있고 "언제 무슨 일이 있었는지"가 없어서, 이 둘이 없으면 아래 3·4번 제안(판정 기준·시각화)이 계산 불가능. 이건 코딩이라 Cursor 담당 영역이고, 저는 필요성과 스키마 초안만 제안.

---

## 3. TOPIK 응시 가능 판단 기준 (D2 공식 제안)

**리서치 근거**: 해외 자격시험 벤치마크 조사 결과 — 모의 80%+ 응시자의 실제 합격률 ~85%, 75-79%는 ~78%, 70-74%는 ~65%로, **단발성 고득점 1회보다 "일정 구간을 꾸준히 유지"가 실제 합격과 더 강하게 연동**된다는 패턴이 반복 확인됨 (여러 공인 자격시험 practice-test 사후분석 공통).

이걸 D1의 기존 임계값(80%=160점)에 그대로 적용 제안:

> **"준비됨" 배지 = 단일 고득점이 아니라 최근 N회 중 일정 비율 충족**
> - 예: 최근 **최종 간이 모의 3회 중 2회 이상**이 80%(160점) 이상 **AND** 오답 태그 재실수율이 지난 2주 대비 하락 추세
> - 1회 요행 고득점만으로는 배지 안 줌(위 리서치의 "일관성 > 단발점수" 패턴 반영), 반대로 1회 저득점 슬럼프로 배지가 바로 사라지지도 않음(3회 중 2회 기준)
> - D2가 이미 정한 "최종 전=추정 / 최종 후=확정" 구도와 자연스럽게 맞음: 최종 간이 모의를 누적해가면서 실시간으로 추정치가 갱신되는 구조

이건 어디까지나 제안 값이고, D17처럼 나중에 ops에서 조정 가능한 파라미터로 두는 게 기존 방향과 일치.

## 4. 성장 과정 시각화 제안 (D3 구체화)

D3가 이미 정한 "객관 데이터(그래프) / 캐릭터 성장 — 별도, 비슷하되 불일치 허용" 구조를 그대로 따르고, 객관 데이터 쪽을 3개 층으로 제안:

1. **구간 내 위치** — 0~200점 축 위에 1급(80-139)·2급(140-200) 밴드를 색으로 표시하고, 최근 최종 간이 모의 점수를 마커로 찍는 가로 게이지. 목표 구간(160-180)을 강조 표시. "n% 합격" 문구 없이 위치만 보여줘서 기존 톤 유지.
2. **오답 개선 추이** — 회차별(가로축=날짜/회차) 오답률 라인 차트. `attempt_log` 시계열이 있어야 그릴 수 있음(2번 항목이 이 시각화의 전제조건).
3. **강점·약점** — 태그(문법/어휘/듣기/읽기 영역)별 정답률을 막대 또는 방사형 차트로. 지금 `state.learner.byTag`에 있는 구조를 그대로 시각화하면 됨(이미 데이터 존재).

캐릭터 성장(아이템 단계)은 이 3개 옆에 별도 트랙으로 나란히 배치 — "객관 지표와 캐릭터가 다르게 갈 수도 있다"는 기존 결정을 시각적으로도 그대로 드러내는 게 D3 취지에 맞음(둘을 억지로 하나의 그래프에 합치지 않기).

---

## 5. 그 기준에 다다르는 성장 과정 설계 제안

기존 루프(SRS 복습 → 오답 태그 감소)에 "정기 측정" 지점을 하나 추가하는 정도의 가벼운 제안:

```
평소: SRS 복습 + 퀴즈 (지금 그대로)
  ↓
마일스톤: 미니모의(예: 10문항, 부담 적게) — 코스 중간중간
  ↓ mock_attempts에 기록, 진행 중 그래프 갱신
코스 후반: 최종 간이 모의(풀세트) — 반복 응시 가능
  ↓ 최근 3회 중 2회 80%+ 충족 시 "준비됨" 배지
```

캐릭터 아이템 언락과는 **완전 분리를 유지하되(D3 결정 존중), 3단계(부츠) 언락에만 "미니모의 최소 1회 응시" 같은 약한 게이트 하나**를 제안 — 완전히 안 겹치면 "캐릭터만 진행되고 객관 지표는 한 번도 안 재본" 학습자가 나올 수 있어서, 최소한의 접점만 하나 둠. 나머지 단계(팬티/무기/방패/왕관)는 지금처럼 참여+이해+개선 점수로 독립.
