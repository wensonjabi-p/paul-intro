# 리서치+제안 — 획순 트레이싱 UI 구현 방법 (2026-07-26, Claude)

> 전제: 모음 캐릭터는 당분간 안 만들기로 확정(Paul). 이 문서는 기존 자음 13개 대상 획순 UI만 다룸.

---

## 결론부터

**Hanzi Writer**(MIT 라이선스, 오픈소스, vanilla JS, 10kb gzip)를 그대로 가져다 쓰고 — 한자 데이터 대신 **자체 제작한 한글 자모 획순 데이터**만 새로 만들어 넣는 방식을 제안. 새로 엔진을 짤 필요 없음, 데이터만 채우면 됨.

## 1. 왜 Hanzi Writer인가

- 정확히 이 기능(글자 획순 애니메이션 + 따라 그리기 퀴즈 + 틀렸을 때 힌트)을 위해 만들어진 라이브러리. 한자·간체/번체 대상이지만 **한글 전용은 없음**(확인됨) — 대신 이 라이브러리의 데이터 구조가 글자 종류에 종속되지 않는 범용 포맷이라 재사용 가능.
- vanilla JS, 프레임워크 무관, 캔버스 또는 SVG 렌더러 선택 가능 — jabi.의 "빌드 시스템 없음" 아키텍처와 궁합 좋음.
- MIT 라이선스라 자유롭게 통합 가능.

## 2. 데이터 형식 (직접 만들어야 하는 부분)

글자 하나당 필요한 것: **`strokes`**(획별 SVG path, 순서대로) + **`medians`**(획의 중심선을 따라가는 좌표점 배열, 채점·애니메이션에 사용). 좌표계는 1024×1024 그리드 고정.

- 한글 자모는 획수가 적음(1~5획, 대부분 직선+간단한 곡선) — 한자 수천 자 분량의 기존 오픈 데이터셋이 필요했던 것과 달리, **jabi. 자음 13개면 직접 손으로 제작 가능한 규모**(대략 13개 × 평균 3획 ≈ 40획 정도).
- 획순 정확성 참고 자료: `MagisterAdamva/hangeul-stroke-order`(CC BY-SA 4.0, 40자 중 35자 획순 SVG 제공) — **그대로 복사하지 말고 참고해서 jabi. 자체 좌표로 재제작**(라이선스가 저작자표시-동일조건변경허락이라 그대로 배포하려면 같은 라이선스 조건이 붙음, 재제작이 깔끔함).

## 3. 동작 방식 (라이브러리가 이미 처리하는 부분)

1. 획순 애니메이션으로 먼저 보여줌
2. 학생이 캔버스/SVG 위에 손가락(모바일)·마우스로 따라 그림
3. 라이브러리가 그려진 점들을 median 경로와 비교해서 정확도 판정(순서·방향·위치)
4. 기본값: **3번 틀리면 자동으로 힌트**(획 강조 표시) — jabi.의 "재촉 안 함" 톤과도 자연스럽게 맞음(바로 정답 안 보여주고 몇 번 시도 기회 줌)

## 4. jabi. 통합 제안

- 기존 퀴즈 데이터(4지선다 `choices` 타입)와 별개로 **신규 문제 타입** 하나 추가(예: `type: "trace"`) — 문제 은행 JSON에 자모 ID만 지정하면 Hanzi Writer 퀴즈 모드가 그 위치에 렌더링되는 구조 제안.
- SRS·오답 태그 체계는 그대로 재사용(`jamo:ㄹ` 같은 태그로, 기존 `grammar:*`/`vocab:*`와 같은 패턴).

## 5. 리스크 · 다음 확인 필요

- **median 좌표 제작이 생각보다 손이 많이 갈 수 있음** — SVG path(윤곽선)는 비교적 쉽지만 median(중심선, 채점 기준)은 획 안쪽 궤적을 정밀하게 잡아야 해서 시행착오 필요.
- **제안**: 13개 전체 착수 전에 자모 2~3개(예: ㄱ, ㅣ, ㅇ처럼 쉬운 것부터)로 파일럿 먼저 만들어서 실제 채점 정확도·제작 소요시간을 확인한 뒤 나머지 확장 여부 결정.
