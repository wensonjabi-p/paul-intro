## 1. 공식 작문 영역 구조 (리서치 확인)

| 문항 | 유형 | 분량 | 배점 | 평가 축 |
|---|---|---|---|---|
| 51~52 | 빈칸에 문장 1개씩 완성 | 문장 단위 | 상대적으로 작음 | 격식체 문어(-습니다/-다) 정확성 |
| 53 | 단문 작문(그래프·정보 설명형) | 200~300자 | 중간 | 내용·과제수행 / 전개구조(도입-전개-마무리) / 언어사용(격식체) |
| 54 | 논술문(주제 의견형) | 600~700자 | **50점**(전체 100점 중 최대 비중) | 논리적 조직(담화 표지 사용) / 문법·어휘의 다양성과 적절성 |

**시사점**: TOPIK II 쓰기는 사실상 **54번 하나가 성패를 좌우**함 — AI 채점 엔진도 54번(논술형) 정확도에 가장 공들여야 함.

## 2. 공식 채점 3축 (TOPIK 공식 채점 기준의 일반적 구조)

1. **내용 및 과제 수행** — 문제가 요구한 항목을 다 다뤘는지, 내용이 충분히 풍부한지
2. **글의 전개 구조** — 문단·단락 구성, 담화 표지(그래서/하지만/따라서 등) 사용, 논리적 흐름
3. **언어 사용** — 문법·어휘의 다양성·정확성, 격식체 일관성(구어체 섞이면 감점), 맞춤법

## 3. AI 채점 프롬프트 설계 제안

```
시스템 프롬프트 (초안):
당신은 TOPIK II 쓰기 54번(600~700자 논술) 채점을 보조하는 코치입니다.
공식 채점 기준(엄격한 시험 채점관 아님, 학습 피드백 목적)을 참고해 아래 3축으로
각각 짧은 평가 + 개선 제안을 주세요. 절대 "합격/불합격"을 단정하지 말고
"이 정도 수준이면 대략 N급 범위" 같은 추천 톤을 쓰세요(D17 정책과 동일).

1. 내용 및 과제 수행 (요구 항목을 다 다뤘는가, 예시/근거가 충분한가)
2. 전개 구조 (담화 표지 사용, 문단 구성, 도입-전개-마무리)
3. 언어 사용 (문법 다양성, 어휘 수준, 격식체 일관성, 맞춤법)

각 축마다: (a) 잘한 점 1개 (b) 고칠 점 1개 (c) 구체적 예문 수정 제안
마지막에: 종합 코멘트 1~2문장(급수 "추천 범위"로, 확정 아님을 명시)
```

**출력 형식**: 기존 힌트 시스템처럼 en/ko/zh 다국어 + 구조화된 JSON(축별 점수 아님, **정성 피드백** 중심 — 정확한 숫자 점수를 AI가 매기면 "공식 점수"로 오인될 위험이 큼, D17의 "보장 아님" 톤과 직결).

## 4. 기존 인프라 재사용 경로

마스터플랜 1.6 "AI weekly summary v0" — Kimi API로 로컬 통계에서 "약점 3가지" 뽑아내는 기능이 이미 설계돼 있음. **같은 API 연동 패턴을 54번 채점에 그대로 확장** 가능 — 새 AI 프로바이더 붙일 필요 없이 기존 연동 방식 재사용.

## 5. 리스크 · 다음 확인 필요

- **공식 세부 배점표(예: 언어사용 몇 점, 구조 몇 점)는 공개 자료로 못 찾음** — 한국교육과정평가원 비공개 자료로 보임. 그래서 **AI 채점은 정확한 점수가 아니라 "정성 피드백 + 대략적 급수 범위"로 설계**하는 게 안전(과도한 정밭성 주장 방지).
- **캘리브레이션 필요**: 착수 시 실제 TOPIK 기출 54번 예시 답안(고득점/저득점 샘플, 공개된 것 있으면)으로 AI 채점 결과가 합리적인지 먼저 검증 후 배포.
- 51~52번(단문 완성)은 채점이 상대적으로 쉬움(정답에 가까운지 grammar-check 수준) — 54번보다 먼저 구현해도 리스크 낮음, 순서상 51→52→53→54로 난이도 올려가며 구현 제안.
