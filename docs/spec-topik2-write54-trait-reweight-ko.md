## 왜 재조정이 필요한가

jabi의 현재 3축(내용/조직/언어)은 공식·준공식 자료를 참고해 만든 **추정치**였음(`topik2-writing-axis-mapping-ko.md`). 이번에 확보한 허영수(2024) 논문은 논설문·설명문 각각 **9개 세부 항목의 실제 배점**(교원 287명 설문 + 요인분석 + 총점-항목 상관분석으로 도출, 임의 배점 아님)을 준다. 이 9항목을 jabi 3축에 정확히 대응시켜보면, **논설문(54번)의 현재 가중치가 실제 배점과 크게 어긋나 있음**이 드러난다.

## 계산 — 논설문(54번) 9항목 → jabi 3축

논설문 100점 배점 (`research-heo2024-writing-rubric-ko.md` 표 그대로):

| jabi 축 | 논문 항목 | 배점 | 축 합계 |
|---|---|---|---|
| **내용(content)** | 논증의 타당성 · 근거의 관련성 · 주장의 명확성 (주장의 설득력 전체) | 14+11+8 | 33 |
| | 내용의 독창성 · 독자에 대한 고려 · 내용의 정확성 (내용의 충실성 전체) | 14+11+8 | 33 |
| | **내용 소계** | | **66** |
| **조직(organization)** | 텍스트의 응집성 | | **15** |
| **언어(language)** | 표현 양식의 적절성 · 문장의 유창성 | 11+8 | **19** |

**핵심 발견**: 논문 구조에서는 "주장의 설득력"과 "내용의 충실성"이 둘 다 사실상 내용 관련 항목이라, 논설문은 **내용이 전체의 66%**를 차지한다. "표현의 적절성"(응집성+격식체+유창성) 34점 중 응집성(15점)은 jabi의 "조직" 축, 격식체+유창성(19점)만 jabi의 "언어" 축에 해당한다.

**현재 jabi 값 (`hub/app/data/topik2/draft-write-54.json` `scoring.traits`)**: content 0.35 · organization 0.30 · language 0.35 — **내용이 크게 저평가되고, 언어가 거의 2배 과대평가**돼 있었음.

## 변경 사항 — `draft-write-54.json`만

```json
"scoring": {
  "traits": {
    "content":      { "weight": 0.66, ... },
    "organization": { "weight": 0.15, ... },
    "language":     { "weight": 0.19, ... }
  }
}
```

(0.66 + 0.15 + 0.19 = 1.00. 논문 원 배점 66/15/19를 반올림 없이 그대로 사용 — 임의 조정 아님.)

**Q53은 변경하지 않음**: 설명문 배점을 같은 방식으로 환산하면 내용≈0.34·조직≈0.33·언어≈0.33이 나오는데(구조의 설명력=조직 33점, 정보의 충실성=내용 34점, 표현의 적절성=언어 33점), 현재 Q53 값(0.4/0.3/0.3)과 차이가 작아(±6점대) 코드 변경 리스크 대비 실익이 낮음. 근거는 [`research-heo2024-writing-rubric-ko.md`](research-heo2024-writing-rubric-ko.md) 설명문 표 참고.

## 격식체(casualOnly) 페널티 — 코드 상수는 안 건드려도 됨

`topik2.js`의 `evaluateFreeText()`에서 해요체/반말만 쓴 글은 `langFormal = 24`(격식체면 100)로 language 서브스코어를 깎는다. 이걸 논문 기준("순수 격식체 위반 최대 손실 = 총점 100점 중 9~10점")과 맞는지 검증:

- fallback 공식(`language = langLen*0.45 + langFormal*0.55`, 체크리스트 없을 때): langLen이 만점(100)이어도 casualOnly면 language = 45 + 0.55×24 = **58.2점**(100점 만점 대비 41.8점 하락).
- 이 하락이 총점에 미치는 영향 = language 가중치 × 41.8 = **0.19 × 41.8 ≈ 7.9점**.
- 체크리스트가 있는 공식(`langCheckAvg*0.35 + langLen*0.3 + langFormal*0.35`)일 때도 = 0.19 × (0.35×76) ≈ **5.1점**.

**둘 다 논문의 9~10점 상한 안에 들어옴** — language 가중치를 0.35→0.19로 낮추는 것만으로 격식체 페널티가 저절로 논문 기준에 맞춰짐. `langFormal` 상수(24/40/100)나 공식 자체는 **건드릴 필요 없음**. (계산 검증은 이 문서에 남겨두니 재도출 불필요.)

## 구현 체크리스트 (Cursor)

1. `hub/app/data/topik2/draft-write-54.json` → `scoring.traits.content.weight = 0.66` · `organization.weight = 0.15` · `language.weight = 0.19`.
2. `hub/app/topik2/topik2.js` 약 367–374행 `resolveTraits()`의 write-essay용 하드코딩 fallback(`content: 0.35, organization: 0.3, language: 0.35`)이 **Q54 전용 폴백인지** 확인 — bank에 `scoring.traits`가 이미 있으면 이 폴백은 안 쓰이므로(367행 `fromBank` 우선) 실사용 영향은 없을 가능성이 높지만, 다른 write-essay 문항이 이 폴백에 의존하고 있다면 그 문항들에도 영향이 없는지 확인만 하고, 없으면 그대로 둬도 됨(별도 수정 불필요).
3. UI 라벨(`w${cfg.weight}` 등)은 `topik2.js` 1102행에서 config 값을 그대로 렌더링하므로 하드코딩 문자열 수정 불필요.
4. **회귀 확인**: `docs/topik2-write54-calibration-samples-ko.md`의 A(격식체 미준수, 얕은 내용)·C(모범)·F(모범) 샘플 텍스트를 실제 플레이어에 붙여넣어 재생 — 기대 방향: **A는 전보다 더 낮아짐**(내용 얕음이 이제 66% 비중이라 더 크게 깎임), **격식체만 문제고 나머지가 좋은 가상 케이스는 전보다 덜 깎임**. 극단값(0점 근접, 100점 근접)이 안 나오는지만 육안 확인.
5. commit 메시지에 이 스펙 문서 경로 언급.
