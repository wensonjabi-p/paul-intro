# UX 리뷰 — 온보딩→퀴즈→분석 실사용 흐름 (2026-07-26, Claude)

> 로컬 서버(`python -m http.server`, `hub/`)로 앱을 직접 실행해 중국어 UI로 온보딩 4단계 → 읽기 모의고사 1세트(10문항) → 분석("나") 탭까지 실제 학습자처럼 걸어봄. 코드 수정 없이 리뷰만.

---

## 🔴 1. 준비도 "등록 CTA"가 1회 시도만으로 뜸 (우선순위 최고)

10문항짜리 연습 세트 **딱 1번**(9/10 정답) 풀었더니 바로 홈 화면과 분석 탭에 이게 떴음:

> "准备度约 80% — 去报名 TOPIK 吗？" **[打开报名网站]**

`estimateReadiness()`(app.js:1142)가 표본 수를 체크하지 않고 `최근3회 평균×0.65 + 마지막×0.35`를 바로 계산 — 시도가 1회뿐이면 사실상 그 1회 점수를 그대로 "90% 준비됨"으로 보여줌.

**왜 문제인가**: `docs/handoff-growth-character-ko.md` D17이 이미 "보장이 아니라 추천" 톤을 정책으로 못박았고, 문구 자체("仅供参考，不构成保证")는 지켜지고 있음 — 하지만 **행동 유도(CTA)는 문구와 별개로 너무 이름**. 처음 써본 학습자가 10분 만에 "등록하세요" 버튼을 보게 되는 건, 지난 리서치(`docs/research-readiness-data-model-ko.md` §3)에서 제안한 "다회차 일관성 확인 후 준비됨 판정"과 정반대 방향.

**제안**: 등록 CTA(그리고 "80%+" 문구 강조)는 **최소 시도 횟수 게이트**(예: 연습 세트 3회 이상 또는 최종 간이 모의 1회 이상) 통과 전엔 숨기고, 그 전까지는 "더 풀어보면 정확한 추정이 나와요" 톤으로 대체하는 걸 제안.

## 🔴 2. 캐릭터 아트가 앱에 전혀 연결 안 됨

`app.js`에 `assets/chars/` 참조가 **0건**. 이번 세션 내내 만든 giyeok 6단계 SVG가:
- 온보딩 파트너 선택 화면 → 그냥 "ㄱ giyeok" 텍스트
- 홈 화면 캐릭터 영역 → "ㄱ giyeok 第2阶·短裤" 텍스트만
- "나" 탭 프로필 → "角色 2/6" 텍스트만

이미지가 어디에도 안 보임. 자산은 다 있는데 배선이 안 됐다는 뜻 — Cursor가 나머지 로스터 만들 때 이 연결 작업도 같이 스코프에 넣어야 할 듯.

## 🟡 3. 캐릭터 성장 속도가 예상보다 훨씬 빠름

연습 세트 **딱 1개** 풀고 stage 1(baby)→stage 2(pants)로 바로 승급함. 원래 설계(D6, "6단계 · 너무 루즈하지도 빡빡하지도 않게")가 코스 전체에 걸친 성장을 의도했는데, 지금 페이스면 로스터 완성 전에도 몇 세트만 풀면 6단계를 다 소진할 수 있어 보임. 참여+이해+개선 가중치 조정 필요해 보임(구현 시 조정 예정이었던 부분, D6 비율 미확정과 연결됨).

## 🟢 4. 오답 태그가 내부 ID 그대로 노출

분석 탭 강점/약점에 `grammar:와/과`, `vocab:형용사` 같은 raw 태그가 그대로 텍스트로 나옴. 초급 중국어 학습자 입장에선 `grammar:`라는 영어 접두사가 의미 불명 — 태그→표시 라벨 매핑이 있으면 좋겠음.

## 🟢 5. 퀴즈 중 이탈 경로 없음

문제 풀이 화면엔 하단 네비게이션(홈/연습/나)이 숨겨지고 뒤로가기 버튼도 없음. 의도적 설계(집중 유도)일 수도 있는데, 확인 차 기록.
